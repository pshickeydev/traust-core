# Python patterns (traust-core)

Adapted from the house `python-patterns` skill. Where they differ, `AGENTS.md` wins: no generic repository/service bases, no result wrappers, no `Any` or `dict` across boundaries, sync code (SQLAlchemy Core).

## Workflow

1. **Clarify** — inputs/outputs, which domain owns it, which class is responsible (`AGENTS.md` → Design rules).
2. **Find the owner** — search for an existing model/service/repository method before adding one.
3. **Build** — models (with their own rules) → repository port → service method → adapter (CLI/`Materializer`) if needed.

## Style

- **Concise** — fewest lines that stay clear; no boilerplate, no speculative helpers
- **OOP for responsibilities** — one class per domain service, policy or repository; behaviour about one entity lives on its model
- **Functional for transforms** — comprehensions over loops when clearer
- **Types always** — every parameter and return annotated; IDs are `UUID` named `<entity>_id`
- **Docstrings 1–2 lines max, comments almost never** — names and types explain. Bloated comments, narration, banners and over-explaining are not allowed at all; the only comment is a one-line non-obvious *why*
- **Effective logging** — follow AGENTS.md → Logging and tracing: module logger (`logging.getLogger(__name__)`), log at boundaries with the correlation ID, right level, no secrets; never log-and-continue on errors

## Patterns

| Need | Use |
|---|---|
| Internal domain object | `Model` / `Entity` (`models/base.py`, strict, frozen) |
| Boundary data (tolerant input) | `Dto` |
| Value object | `@dataclass(frozen=True, slots=True)` with a `parse` classmethod |
| Closed set | `StrEnum`, or `models/vocabulary.py` for contracts enums |
| Identifier | `UUID`, named `<entity>_id`; inherited `id` on `Entity`, generated by the database on insert, `None` until saved — never minted in code |
| Optional / unknown | `T \| None` (unknown is `None`, never `0` or `""`) |
| Config | a section on `context/config.py` `Config`; secrets by env-var name only |
| Error with context | `raise NotFoundError(f"finding {id}") from e` (`traust_core.v1.errors`) |
| Resources | context managers (`with uow:`) |
| External process / clock | `ProcessRunner` / `Clock` — never `subprocess` or `datetime.now()` |

## Avoid (the slop we are removing)

- Generic `Repository[T]` / `Service[T]` bases, `save`/`delete` CRUD, singletons, factories without a second implementation
- `ServiceResult`-style success/error wrappers — raise typed errors; adapters translate to `JobResult`
- `dict[str, Any]`, `Any`, bare `str` IDs or kinds across a function boundary
- Re-implementing something another module owns (rating, identity, disposition, rendering, escaping)
- Reading files, env vars or databases from services; building paths anywhere but adapters

## Checklist

- Every signature typed? IDs typed, enums for closed sets?
- No comment that narrates or over-explains? Docstrings ≤ 2 lines?
- `Model`/`Dto`/frozen dataclass chosen correctly?
- Behaviour on the model when it is about one entity's own state?
- One owner — no second implementation of an existing capability?
- Errors from `traust_core.v1.errors`, wrapped with `from e`?
- `make lint-fix && make test` green?
